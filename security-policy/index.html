Hotlap

Security Policy

Effective 12 September 2026

Reporting a vulnerability

Please report security issues privately through GitHub private vulnerability reporting rather than a public issue. You will get an acknowledgement, and a fix or mitigation will ship in the next release once confirmed.

Scope

Hotlap's own code: the host server, the desktop, mobile, and CLI apps, and the release pipeline. Issues in upstream T3 Code should also go to T3 Code's security page; Hotlap tracks upstream and ships its fixes automatically.

How Hotlap is secured

  • Every client must pair with a host using a one-time token; unpaired connections are refused.
  • macOS builds are signed with a Developer ID and notarized by Apple; iOS builds ship through TestFlight and the App Store.
  • Releases are built by GitHub Actions from a tagged commit, and the npm package is published with a Trusted Publisher (no long-lived tokens).
  • There is no hosted backend, so there is no central store of user data to breach.
